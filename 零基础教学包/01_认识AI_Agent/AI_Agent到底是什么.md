# AI Agent 到底是什么

## 1. 用一句话理解

普通 AI 像“会回答问题的人”。  
AI Agent 像“会使用工具做事的人”。

普通聊天 AI 通常只能：

- 回答问题。
- 写一段文字。
- 给建议。

AI Agent 可以进一步：

- 读取你电脑里的文件。
- 修改或生成文件。
- 运行 Python/R/命令行。
- 调用浏览器。
- 使用 Skills。
- 把结果保存到指定目录。

## 2. 科研场景中的 Agent

科研 Agent 可以帮你做：

- 读论文。
- 建文献矩阵。
- 检查引用。
- 整理数据。
- 跑描述统计。
- 做文本挖掘。
- 写论文段落。
- 审查论文漏洞。

但是它不能替你做三件事：

1. 判断研究问题是否真正重要。
2. 判断理论机制是否站得住。
3. 判断因果识别假设是否成立。

这三件事必须由研究者负责。

## 3. Agent、Skill、MCP、Subagent 的区别

| 概念 | 零基础解释 | 科研例子 |
|---|---|---|
| Agent | 会使用工具的 AI 助手 | 让它读文件、跑代码、生成报告 |
| Skill | 封装好的专项能力 | 文献综述 Skill、文本分析 Skill |
| MCP | 让 Agent 连接外部工具的接口 | 连接 Zotero、飞书、数据库 |
| Subagent | 分工合作的小助手 | 一个找文献，一个审方法，一个写结果 |
| Hook | 自动触发的检查动作 | 保存前检查是否覆盖 raw 数据 |
| Cron | 定时任务 | 每周自动检索新文献 |

## 4. 为什么要用 Skills

如果你每次都手写很长提示词，容易出现三个问题：

- 忘记关键步骤。
- 输出格式不稳定。
- Agent 自由发挥太多。

Skill 的作用是把经验固定下来：

```text
什么时候用
需要什么输入
执行哪些步骤
调用哪些脚本
输出什么文件
哪些事情不能做
```

所以，Skill 不是魔法，而是“标准作业流程”。
