# 第 01 讲：AI Agent 科研入门与部署

副标题：从零搭建可复用的科研 Agent 工作区

## 一、课程定位

这节课不是“介绍几个 AI 工具”，而是带学生搭建一套后续课程都能复用的科研基础设施。学生完成本讲后，应能回答并执行以下问题：

- 什么时候用 Codex、Claude Code、OpenClaw、Hermes。
- 国内模型和国外模型如何按任务选择。
- 中转站、API Key、模型能力、费用和隐私如何评估。
- `AGENTS.md`、`CLAUDE.md`、`MEMORY.md`、`SOUL.md`、`USER.md` 应该写什么。
- Skills 是什么，应该放根目录还是项目工作区。
- MCP 是什么，Ai4Scholar-MCP、AMiner-MCP、飞书/IMA 渠道分别解决什么问题。
- 如何把每天的科研任务部署成可追踪、可复现的 Agent 工作流。

建议课时：3 小时。

## 二、本讲模板

### 这节课解决什么科研问题和需求

科研新手使用 Agent 最大的问题不是“不会问问题”，而是没有基础设施：

1. 工具混用：同一件事不知道该交给 Codex、Claude Code、OpenClaw 还是 Hermes。
2. 模型乱选：不知道什么时候用国内模型，什么时候用国外模型。
3. 配置散落：API Key、MCP、Skills、记忆文件没有统一管理。
4. 输出不可复现：今天 Agent 做出的流程，明天学生自己复现不了。
5. 文献不可信：Agent 可能生成看似合理但不可核验的引用。
6. 渠道割裂：飞书、IMA、知识库、文献平台和本地工作区没有打通。

本讲目标是让学生当场完成一个“最小可用科研 Agent 工作区”。

### Agent 应该怎么执行

课堂采用 8 步执行流：

1. 建立项目文件夹。
2. 写入项目级记忆文件。
3. 选择 Agent。
4. 选择模型和中转站。
5. 复制本项目需要的 Skills。
6. 配置 MCP。
7. 连接飞书/IMA 渠道。
8. 执行一次低风险科研任务并记录日志。

建议项目结构：

```text
第01讲_我的Agent工作区/
├─ AGENTS.md
├─ CLAUDE.md
├─ MEMORY.md
├─ SOUL.md
├─ USER.md
├─ project_status.md
├─ research_log.md
├─ skills/
├─ input/
├─ literature/
├─ data/
│  ├─ raw/
│  └─ processed/
├─ output/
└─ configs/
   ├─ mcp.example.json
   └─ env.example
```

### 输出文件应该长什么样

本讲结束时，每个学生至少交付 6 个文件或文件夹：

| 输出 | 合格标准 |
|---|---|
| `AGENTS.md` | 包含学科背景、研究方向、引用规则、理论使用规则、写作风格和安全规则 |
| `skills/` | 至少包含 Ai4Scholar、AMiner、项目管理相关 Skills |
| `configs/mcp.example.json` | 包含 Ai4Scholar 和 AMiner MCP 配置模板，密钥用环境变量占位 |
| `project_status.md` | 写清当前项目目标、输入、下一步任务 |
| `research_log.md` | 记录一次 Agent 执行过程、输出和人工核验结果 |
| `output/first_agent_test.md` | 一次文献检索或学者检索测试结果，注明“已核验/未核验” |

### 哪些地方必须人工核验

以下内容不能完全交给 Agent：

- API Key 是否泄露。
- 模型费用和调用额度。
- 学生是否把敏感数据上传到不合规模型。
- 文献是否真实存在。
- DOI、PMID、arXiv ID、作者、期刊、年份是否匹配。
- AMiner 返回的作者是否同名误配。
- Ai4Scholar/AMiner/MCP 返回数据是否过期或失败。
- 飞书/IMA 是否有组织授权和文档权限。
- Agent 输出是否把“相关”误写成“因果”。

### 学生课后作业

提交一个压缩包或文件夹，命名为：

```text
姓名_第01讲_Agent科研工作区
```

必须包含：

1. 项目文件夹截图。
2. `AGENTS.md`。
3. `configs/mcp.example.json`。
4. `research_log.md`。
5. 至少 1 个 Skill 文件夹。
6. 一次 Ai4Scholar 或 AMiner 的测试记录。
7. 300 字反思：本节课后，你更适合先用哪个 Agent，为什么。

评分重点：

- 文件结构是否清楚。
- 是否没有泄露密钥。
- Skills 是否放在工作区而不是误装到全局根目录。
- MCP 配置是否可读、可迁移。
- 文献或学者结果是否标注了人工核验状态。

## 三、四类 Agent 的科研分工

| Agent | 核心定位 | 最适合的科研任务 | 不适合直接承担的任务 |
|---|---|---|---|
| Codex | 本地工作区型编码与文件操作 Agent | 整理资料、写脚本、生成 docx/pptx/xlsx、批量处理数据、维护 Skills 库 | 直接替代真实文献数据库；凭记忆编造引用 |
| Claude Code | 终端型长上下文代码/文档 Agent | 大型代码库理解、长文档重构、项目级记忆、MCP 工具调用、论文草稿批改 | 未配置工具时直接声称完成外部检索 |
| OpenClaw | Agent 网关、插件和多工具连接平台 | 接入 OpenClaw 插件、MCP、AI4Scholar、浏览器与渠道工具 | 无版本确认时盲目照搬插件命令 |
| Hermes | 本地优先、可配置记忆和工具的 Agent 客户端 | 适合作为课程中的可配置 Agent 框架，演示 `SOUL/MEMORY/USER` 与工具组合 | 版本差异较大，安装命令必须按当前官方或课程包确认 |

建议学生按任务选择：

| 任务 | 优先 Agent | 理由 |
|---|---|---|
| 本地文件整理、生成 Word/PPT/Excel | Codex | 文件操作能力强，适合当前资料库 |
| 长代码库阅读、长论文结构调整 | Claude Code | 长上下文和项目记忆适合复杂文本 |
| 统一接入 AI4Scholar、浏览器、MCP、插件 | OpenClaw | 更像工具网关 |
| 演示可配置人格、记忆、工具和本地 Agent 行为 | Hermes | 便于讲解 Agent 配置层 |
| 飞书/IMA 协作和消息渠道 | OpenClaw 或带 Lark/渠道工具的 Agent | 关键是通道权限和工具配置 |

## 四、部署教学

### 1. Codex 部署

用途：本地科研工作区自动化、资料整理、文档生成、脚本执行、Skills 管理。

基本步骤：

```powershell
# 1. 准备 Node.js 或官方推荐环境
node --version

# 2. 安装 Codex CLI；具体包名以 OpenAI 官方说明为准
npm install -g @openai/codex

# 3. 进入科研项目
cd "D:\AI科研训练营\第01讲_我的Agent工作区"

# 4. 启动
codex
```

项目级配置重点：

- 在项目根目录放 `AGENTS.md`。
- 把项目专用 Skills 放在 `skills/`，不要默认塞进 `C:\Users\用户名\.codex\skills`。
- 把环境变量写入系统环境变量或私有 `.env`，不要写进共享文档。

Codex 在本课程中的典型任务：

- 读取一批 PDF 并生成论文卡片。
- 根据模板生成 Word 手册、PPT 课件和 Excel 筛选表。
- 把研究项目拆成输入、脚本、输出、日志。
- 检查本地 Skills 库是否完整。

### 2. Claude Code 部署

用途：终端中进行代码、长文档和项目记忆协作。

基本步骤：

```powershell
# 1. 检查 Node.js
node --version

# 2. 安装 Claude Code；以 Anthropic 官方当前命令为准
npm install -g @anthropic-ai/claude-code

# 3. 进入科研项目
cd "D:\AI科研训练营\第01讲_我的Agent工作区"

# 4. 启动
claude
```

记忆文件重点：

- `CLAUDE.md` 用于 Claude Code 项目记忆。
- 项目根目录的 `CLAUDE.md` 写项目规则。
- 用户级或全局记忆写稳定偏好，不写密钥。
- 课堂建议把 `AGENTS.md` 与 `CLAUDE.md` 保持内容一致，但不要让文件无限膨胀。

Claude Code 在本课程中的典型任务：

- 长篇论文结构诊断。
- 大型项目代码理解。
- 长上下文文献综述整理。
- 基于 MCP 的外部工具调用。

### 3. OpenClaw 部署

用途：把 Agent、插件、MCP、浏览器和科研工具统一接入。

OpenClaw 在本课程中主要承担：

- 接入 AI4Scholar 插件或 MCP。
- 管理 OpenClaw gateway。
- 连接多模型、多工具、多渠道。

AI4Scholar 插件模式示例：

```bash
# 根据 OpenClaw 当前版本选择正确插件命令
openclaw plugins install ai4scholar

# 某些版本或插件源可能使用 clawhub 前缀
openclaw plugins install clawhub:ai4scholar
```

配置示例：

```json
{
  "ai4scholar": {
    "enabled": true,
    "config": {
      "apiKey": "${AI4SCHOLAR_API_KEY}"
    }
  }
}
```

重启网关：

```bash
openclaw gateway stop
openclaw gateway start
openclaw plugins list
```

注意：如果 Windows 插件安装失败，优先改用 MCP 轻量模式，避免把课堂时间耗在环境问题上。

### 4. Hermes 部署

用途：讲解 Agent 的可配置记忆、人格、用户画像、工具与本地执行逻辑。

Hermes 的生态版本可能差异较大，课堂不强行写死安装命令。若使用 Nous Research 的 Hermes Agent，常见路径是通过官方仓库或安装脚本部署；Windows 学生可优先使用 WSL 或 Git Bash。

课堂配置重点：

```text
SOUL.md    Agent 的原则、边界、语气和科研伦理
USER.md    使用者背景、研究方向、写作偏好
MEMORY.md  长期记忆、项目进展、可复用经验
TOOLS.md   可用工具、MCP、Skills、脚本入口
```

Hermes 在本课程中的典型任务：

- 演示“灵魂文件”和“记忆文件”如何影响 Agent 行为。
- 演示不同用户画像如何改变科研写作建议。
- 演示工具/技能显式装配后，Agent 才能可靠调用外部能力。

人工核验要求：

- 安装命令必须按当前官方文档或课程包版本确认。
- 不要把 Hermes 的“人格设定”写成替代理论或替代事实核验。

## 五、中转站与模型选择

课堂使用以下网站作为模型选择参考入口：

```text
https://hvoy.ai/model-select
```

选择模型时不只看“哪个最强”，而是按任务分配：

| 任务 | 更适合的模型类型 | 选择依据 |
|---|---|---|
| 本地脚本、数据清洗、PPT/Word 生成 | 强代码模型 | 工具调用、代码可靠性、成本 |
| 英文学术写作、审稿式修改 | 强推理/长上下文模型 | 逻辑、语气、篇章结构 |
| 中文资料整理、飞书协作 | 国内模型或中文强模型 | 稳定访问、中文理解、合规 |
| 文献检索与引用核验 | 模型 + MCP/数据库 | 不能只靠模型记忆 |
| EEG/BCI 深度学习代码 | 强代码模型 + 本地运行环境 | 可复现和调试能力 |

国内模型优点：

- 国内网络可访问性更好。
- 中文任务和本土平台集成更方便。
- 一些场景费用更低。
- 数据合规与组织审批更容易处理。

国外模型优点：

- 前沿推理、复杂代码、英文论文写作通常更强。
- 长上下文和工具生态更成熟。
- 对跨学科英文材料处理能力较好。

选择时必须人工核验：

- 是否允许上传未公开数据。
- 是否支持工具调用、MCP、长上下文、文件输入。
- 是否支持结构化输出。
- 费用是否可控。
- 中转站是否稳定，是否有日志留存和隐私风险。

## 六、记忆、灵魂、用户画像 MD 文件

### 1. `AGENTS.md`

项目级协作指令，建议包含：

```markdown
# 项目协作规则

## 用户背景
- 学科：管理学、心理学、神经科学、计算机科学交叉
- 研究方向：EEG/ERP、BCI、HCI、神经营销、文本挖掘

## 文献规则
- 必须引用真实文献
- 无法核验时必须标注“未核验”
- 禁止编造 DOI、作者、期刊、年份

## 理论规则
- 理论必须解释机制
- 禁止标签化套用理论

## 写作风格
- 简洁、准确、有推进感
- 避免套话和空泛表达

## 安全规则
- 不输出 API Key
- 不上传敏感数据到不合规模型
```

### 2. `CLAUDE.md`

Claude Code 项目记忆。建议把 `AGENTS.md` 的关键规则同步进去，但保持简短：

```markdown
# Claude Code Project Memory

- 本项目面向管理学/心理学/神经科学/计算机科学交叉研究。
- 所有引用必须真实可核验。
- EEG/ERP/BCI 任务必须检查事件码、被试划分和数据泄漏。
- 写作要避免空话，优先给出可执行修改。
```

### 3. `SOUL.md`

Agent 行为原则，不写具体事实：

```markdown
# Agent Soul

- 以科研严谨性优先。
- 遇到无法核验的信息，明确说无法确认。
- 不迎合不成立的理论或方法设计。
- 先保护数据安全，再追求自动化效率。
```

### 4. `USER.md`

用户画像：

```markdown
# User Profile

- 身份：博士生。
- 目标：C刊、SSCI、SCI。
- 方法偏好：定量研究、算法开发、EEG、ERP、机器学习、深度学习、文本挖掘、因果推断、情景实验。
- 输出偏好：中文和英文都支持。
```

### 5. `MEMORY.md`

长期项目记忆：

```markdown
# Research Memory

## 已确定方向
- ...

## 已排除方向
- ...

## 可复用文献
- ...

## 可复用代码和数据流程
- ...

## 待人工核验
- ...
```

## 七、Skills 是什么，怎么放

### 1. Skills 的定义

Skill 是一个本地文件夹，至少包含：

```text
skill-name/
└─ SKILL.md
```

也可以包含：

```text
skill-name/
├─ SKILL.md
├─ scripts/
├─ references/
├─ assets/
└─ templates/
```

`SKILL.md` 的作用是告诉 Agent：

- 什么时候使用这个能力。
- 输入需要什么。
- 执行步骤是什么。
- 输出格式是什么。
- 哪些安全边界不能越过。

### 2. 怎么下载或复制 Skills

本课程不建议学生一开始把所有 Skills 安装到全局根目录。推荐从本地功能分类库按项目复制：

```powershell
cd "<本项目路径>\本地Skills功能分类库"

# 预览文献类 Skills
powershell -ExecutionPolicy Bypass -File .\00_工具脚本\copy_skill_to_workspace.ps1 `
  -Category 文献 `
  -Workspace "D:\AI科研训练营\第01讲_我的Agent工作区" `
  -DryRun

# 复制指定 Skills
powershell -ExecutionPolicy Bypass -File .\00_工具脚本\copy_skill_to_workspace.ps1 `
  -SkillName ai4scholar-research,aminer-mcp-research `
  -Workspace "D:\AI科研训练营\第01讲_我的Agent工作区"
```

### 3. 放根目录还是工作区

| 放置位置 | 优点 | 风险 | 课堂建议 |
|---|---|---|---|
| Agent 根目录 | 全局可用，省事 | 容易污染所有项目，学生不知道 Agent 为什么触发某个 Skill | 高年级或固定工作流再用 |
| 项目工作区 `skills/` | 可复现、可交作业、可按项目隔离 | 每个项目需要复制 | 本课程默认方案 |
| 临时复制 | 快速测试 | 容易丢失和不可追踪 | 只用于演示 |

## 八、MCP 是什么

MCP 即 Model Context Protocol，可以理解为 Agent 调用外部工具、数据源和服务的一套标准接口。对科研来说，它解决的问题是：

- Agent 不再只靠模型记忆回答文献问题。
- 可以连接真实数据库、文献平台、文件系统、浏览器、飞书和 Zotero。
- 工具调用过程更可控，可记录，可复现。

### Ai4Scholar-MCP

适合任务：

- 真实论文搜索。
- DOI/PMID/arXiv 信息核验。
- PDF 和全文阅读。
- 引用网络追踪。
- 自动引用和 BibTeX。
- 科学绘图能力。

配置示例：

```json
{
  "mcpServers": {
    "ai4scholar": {
      "url": "https://mcp.ai4scholar.net/sse",
      "headers": {
        "Authorization": "Bearer ${AI4SCHOLAR_API_KEY}"
      }
    }
  }
}
```

### AMiner-MCP

适合任务：

- 学者画像。
- 作者同名消歧。
- 机构/团队分析。
- 专利和应用成果发现。
- 学术趋势和知识图谱。
- 与 Ai4Scholar、OpenAlex、CNKI 交叉核验。

配置示例：

```json
{
  "mcpServers": {
    "aminer": {
      "url": "https://mcp.aminer.cn/sse",
      "headers": {
        "Authorization": "Bearer ${AMINER_MCP_TOKEN}"
      }
    }
  }
}
```

### 课堂判断规则

| 问题 | 优先工具 |
|---|---|
| 这篇论文是否真实、DOI 是否对 | Ai4Scholar / OpenAlex / Crossref |
| 这个学者是谁、属于哪个机构、有哪些合作网络 | AMiner |
| 这篇论文该怎么进入 Zotero | Zotero / pyzotero |
| 这段 PDF 里表格怎么抽取 | pdf / markitdown / docx |
| 这件事是否能自动同步到飞书 | lark-doc / lark-base / lark-im |

## 九、飞书 / IMA 渠道连接

本讲只讲通用连接逻辑，不要求所有学生当场完成组织级授权。

通道结构：

```text
学生请求
  → 飞书/IMA 消息或文档
  → Agent 网关或客户端
  → 模型
  → Skills / MCP / 本地脚本
  → 输出回飞书/IMA 或本地工作区
```

飞书常见连接对象：

| 对象 | 用途 |
|---|---|
| 飞书文档 | 写作、课件、会议纪要 |
| 飞书知识库 | 课程资料、论文卡片、方法手册 |
| 飞书多维表格 | 文献筛选表、实验进度、任务看板 |
| 飞书即时消息 | 触发 Agent、接收摘要、提醒任务 |
| 飞书任务 | 周计划、论文修改、投稿清单 |

IMA 或其他渠道连接时，按同一原则处理：

- 确认渠道是否支持 Webhook、Bot、MCP、插件或 API。
- 确认消息是否能带文件、链接和上下文。
- 确认权限边界。
- 先做低风险测试，不传未公开数据。

## 十、Agent 日常任务部署

每天使用 Agent 不应该从一句“帮我看看”开始，而应该从任务卡开始。

### 标准任务卡

```markdown
# 今日 Agent 任务

## 目标
用真实文献检索“AI agent 在科研工作流中的应用”，形成 20 篇候选文献表。

## 输入
- 关键词：AI agent, research workflow, scholarly search, literature review automation
- 时间范围：2021-2026
- 数据库：Ai4Scholar, OpenAlex, AMiner

## 可用 Skills
- ai4scholar-research
- aminer-mcp-research
- citation-management

## 执行要求
- 每篇论文必须有标题、作者、年份、期刊/会议、DOI 或 URL。
- 无法核验的条目标注“未核验”。
- 不要编造引用。

## 输出
- literature/candidate_papers.xlsx
- literature/search_log.md
- literature/unverified_items.md

## 人工核验
- 检查 DOI。
- 检查是否为同名作者误配。
- 检查主题是否偏离管理学/心理学/神经科学/计算机科学交叉。
```

### Agent 执行后必须更新

```text
project_status.md
research_log.md
unverified_items.md
```
