# 第 09 讲零基础实操教程：文本挖掘、LLM 标注与变量构造

本讲目标：让完全没有文本挖掘基础的学生，从一份原始文本数据出发，完成文本清洗、标签设计、LLM/机器标注、可靠性审计和文本变量构造。

## 3. 第三步：写 AGENTS.md

把下面内容放入 `AGENTS.md`：

```markdown
# 第09讲工作区 Agent 指令

你是文本挖掘、LLM 标注与变量构造助手。

原则：
- 禁止编造标签、样本量、准确率、一致性指标或文本内容。
- 禁止把词频、主题、情感分数直接等同于理论构念。
- 原始文本只读保存；任何清洗都输出新文件。
- LLM 标注必须遵守 codebook，不得自行扩展标签定义。
- API key 不得写入文档、脚本或输出文件。
- 含个人信息、敏感信息或版权风险的文本必须先脱敏和审计。
- 所有文本变量必须能追踪到清洗规则、标注准则、模型参数和人工核验。
```

## 4. 第四步：准备原始文本数据

最简单的数据表必须包含：

```text
doc_id,text,source,date
```

如果你有评论数据：

```text
doc_id,text,source,date,rating,user_id
```

如果你有企业公告或年报：

```text
doc_id,text,firm_id,year,industry,source
```

如果你有访谈：

```text
doc_id,text,interviewee_id,time_point,question_id
```

把原始文件放入：

```text
data/raw/
```

命名示例：

```text
data/raw/raw_text_data.xlsx
```

## 5. 第五步：让 Agent 做文本数据盘点

复制给 Agent：

```text
请读取 data/raw/ 下的文本数据，生成 textmining/text_data_inventory.xlsx 的内容草稿。

请检查：
1. 文件名、文件类型、编码和行数。
2. 文档 ID 列、文本列、时间列、来源列、分组列。
3. 是否存在重复文本、空文本、过短文本、异常长文本。
4. 是否包含个人信息、敏感信息、版权或平台协议风险。
5. 后续变量构造的最小可用数据单位是什么：文档、用户、企业、年份、平台还是事件。

不要修改原始数据。把待人工核验项单独列出来。
```

## 6. 第六步：写文本清洗计划

复制给 Agent：

```text
请基于 text_data_inventory.xlsx，生成 textmining/text_cleaning_plan.md。

必须写清：
1. 保留哪些列。
2. 去除哪些噪声：HTML、URL、表情、重复空格、模板文本、免责声明等。
3. 是否分句、分段或按整篇文档分析。
4. 中文分词工具、停用词表、自定义词典。
5. 专业词如何保护，例如 AI Agent、ChatGPT、脑机接口、ERP、Zotero。
6. 去重规则和异常文本处理规则。
7. 输出文件路径：data/clean/text_clean_v1.csv。
8. 所有清洗步骤不得覆盖原始数据。
```

## 7. 第七步：定义文本变量

文本变量不是“我想算什么”，而是“理论上它代表什么”。

复制给 Agent：

```text
请基于我的研究问题和文本数据，生成 textmining/text_variable_definition.md。

每个文本变量必须包括：
1. 变量名。
2. 理论构念。
3. 构念定义。
4. 文本中可观察证据。
5. 正例、反例、边界例。
6. 可选技术路线：词典、TF-IDF、主题模型、监督分类、LLM 标注、embedding 相似度。
7. 进入实证模型的单位：文档级、用户级、企业-年级、事件级。
8. 不能支持的解释。
```

示例：

```text
变量：ai_uncertainty_expression
构念：不确定性表达
文本证据：可能、或许、不确定、需要人工核验、存在误差、模型无法保证等。
不能支持：不能直接等同于真实风险水平。
```

## 8. 第八步：选择技术路线

按下面规则选择：

| 研究需求 | 推荐路线 |
|---|---|
| 看高频词、专有词、基础分布 | 分词 + 词频 / TF-IDF |
| 构造已有理论词典变量 | 词典法 |
| 判断正负情绪或态度 | 情感分析 |
| 探索大规模文本主题 | LDA / BERTopic |
| 已有标签样本，想批量分类 | sklearn / BERT / ERNIE |
| 标签复杂、需要语义判断 | LLM 标注 + 人工复核 |
| 比较文本相似度 | TF-IDF / embedding similarity |

让 Agent 输出：

```text
请生成 textmining/route_selection.md。

对每个目标文本变量，判断最合适路线，并说明：
- 为什么选这条路线。
- 需要什么输入。
- 输出什么变量。
- 主要风险是什么。
- 人工核验怎么做。
```

## 9. 第九步：基础文本处理实操

如果已经复制了 `text-analysis-basic`，可参考下面命令。

分词：

```powershell
python .\skills\text-analysis-basic\scripts\jieba_tokenize.py `
  .\data\clean\text_clean_v1.csv `
  --text-column text `
  --output .\textmining\tokenized_text.csv
```

词频：

```powershell
python .\skills\text-analysis-basic\scripts\frequencies.py `
  .\textmining\tokenized_text.csv `
  --text-column tokens `
  --output .\textmining\word_frequency.xlsx
```

TF-IDF：

```powershell
python .\skills\text-analysis-basic\scripts\vectorize.py `
  .\data\clean\text_clean_v1.csv `
  --method tfidf `
  --text-column text `
  --output .\textmining\tfidf_features.xlsx
```

核验：

- 关键专业词是否被拆错。
- 停用词是否误删理论关键词。
- 高频词是否主要是平台模板、免责声明或无意义词。

## 10. 第十步：设计 annotation codebook

复制给 Agent：

```text
请基于 text_variable_definition.md，生成 textmining/annotation_codebook.md。

每个标签必须包括：
1. 标签名。
2. 定义。
3. 标注单位。
4. 何时标 1，何时标 0。
5. 正例 3 条。
6. 反例 3 条。
7. 边界例 3 条。
8. 冲突标签处理规则。
9. 不确定时如何标注。
10. 禁止根据文本外信息推断。
```

## 11. 第十一步：抽样人工标注

建议先抽：

```text

```

然后填写：

```text
annotation_sample.xlsx
```

至少包含：

```text
doc_id,text,human_label_1,human_label_2,llm_label,disagreement,error_type,final_label
```

## 12. 第十二步：LLM 标注实操

安全要求：

- API key 只能放在环境变量。
- 不要把 API key 写进提示词、脚本、Excel 或 Markdown。
- 含个人信息的文本先脱敏。

设置环境变量示例：

```powershell
$env:OPENAI_API_KEY="你的key不要写入任何文件"
$env:OPENAI_BASE_URL="https://你的中转站/v1"
```

让 Agent 先生成标注计划，不直接执行：

```powershell
python .\skills\big-data-labeling-variable-construction\scripts\prepare_labeling_plan.py `
  .\data\clean\text_clean_v1.csv `
  --category openai_llm `
  --output-dir .\textmining\llm_labeling_plan
```

重要：该 Skill 要求先展示计划，学生确认后才能执行。

确认语句必须是：

```text
确认无误，请执行
```

## 13. 第十三步：一致性与可靠性审计

复制给 Agent：

```text
请读取 annotation_sample.xlsx，生成 textmining/reliability_report.md。

请报告：
1. 人工标注员之间的一致率和 Cohen's Kappa 或 Krippendorff's Alpha。
2. LLM 与最终人工标签的一致率。
3. 每个标签的 precision/recall/F1，如可计算。
4. 错误类型：漏标、误标、边界例、否定句、讽刺、文本过短、语境依赖。
5. 哪些标签需要改 codebook。
6. 哪些标签不能批量自动化。
```

## 14. 第十四步：构造最终文本变量

复制给 Agent：

```text
请基于清洗后文本、标注结果、词典/主题/情感/分类模型输出，生成 textmining/features.xlsx 和 textmining/feature_dictionary.xlsx。

每个变量必须说明：
- 变量名。
- 构造方法。
- 输入文件。
- 参数。
- 取值范围。
- 理论解释。
- 不能支持的解释。
- 是否需要标准化、聚合或滞后处理。
```

示例变量：

```text
ai_attention_score
risk_expression_ratio
positive_sentiment_score
topic_ai_governance_prob
trust_signal_label
uncertainty_expression_label
text_similarity_to_policy
```

## 16. 最后审计

复制给 Agent：

```text
请以严格审稿人视角审计本工作区，生成 qc/text_variable_audit.md。

检查：
1. 文本来源合规。
2. 原始数据是否被覆盖。
3. 清洗规则是否可复现。
4. 构念定义是否清楚。
5. codebook 是否足够具体。

10. 论文解释是否过度。

输出 pass/revise/fail，并列出必须修改项。
```
