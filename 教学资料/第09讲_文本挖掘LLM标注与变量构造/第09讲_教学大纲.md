# 第 09 讲：文本挖掘、LLM 标注与变量构造

副标题：从原始文本到可解释、可复核、可进入实证模型的研究变量

## 一、课程定位

第 08 讲解决“有变量后怎么分析”的问题，第 09 讲解决“文本如何变成变量”的问题。学生常见错误不是不会跑 NLP，而是把词云、主题词、情感分数直接当成理论变量，缺少构念定义、标注准则、可靠性检验和变量有效性说明。

本讲目标是让学生掌握一条完整链路：

```text
原始文本 → 数据盘点 → 清洗规则 → 文本单元 → 构念定义 → 标注/建模方案
→ 可靠性审计 → 特征/变量构造 → 变量字典 → 与第 08 讲统计分析衔接
```

## 二、本讲模板

### 这节课解决什么科研问题和需求

本讲解决 10 类问题：

1. 有评论、年报、公告、访谈、社媒、论文摘要等文本，但不知道如何进入实证分析。
2. 会分词、词频和词云，但不知道这些结果能解释什么理论变量。
3. 想用 LLM 标注文本，但没有 codebook、标签定义、示例和人工复核。
4. 把情感分数、主题概率或关键词频率直接当成变量，缺少有效性论证。
5. 不知道词典法、机器学习、深度学习、主题模型和 LLM 标注分别适合什么问题。
6. 中文文本清洗、分词、自定义词典和停用词处理随意，导致结果不可复现。
7. 训练集、验证集、测试集划分不规范，出现数据泄漏。
8. 没有标注一致性、人工复核和偏差审计。
9. 文本变量与理论构念不匹配，论文中解释站不住。
10. 文本特征无法和第 08 讲的回归、中介、DID 或机器学习分析衔接。

### Agent 应该怎么执行

本讲采用 13 步执行流：

1. 创建文本挖掘工作区。
2. 复制本讲 Skills。
3. 写 `AGENTS.md`，限制不编造标签、不泄露隐私、不用未核验变量。
4. 建立文本数据盘点表。
5. 做文本伦理、隐私、版权和敏感信息审计。
6. 写清洗规则：去重、去噪、分句、分词、停用词、自定义词典。
7. 建立文本变量构念定义表。
8. 选择技术路线：词典、TF-IDF、情感、主题模型、监督分类、LLM 标注或深度学习。
9. 设计 annotation codebook。
10. 抽样人工标注并做 LLM 试标注。
11. 做一致性、偏差、漂移和幻觉审计。
12. 生成特征表和变量字典。
13. 生成可进入第 08 讲分析的数据表和变量构造报告。

### 哪些地方必须人工核验

| 风险 | 人工核验 |
|---|---|
| 构念定义 | 文本变量是否真的代表理论概念，而不是方便计算的代理 |
| 文本来源 | 爬取、下载、使用和存储是否合规 |
| 个人信息 | 是否包含姓名、手机号、邮箱、机构、账号等敏感信息 |
| 分词词典 | 专业词、机构名、产品名、学科术语是否被错误切分 |
| 停用词 | 是否误删理论关键字 |
| LLM 标注 | 标签是否越界、是否凭常识推断文本没有的信息 |
| 训练测试划分 | 同一作者、企业、事件或重复文本是否跨训练/测试泄漏 |
| 主题模型 | 主题数是否可解释，不要把主题词硬贴理论标签 |
| 情感分析 | 词典或模型是否适配管理学/心理学语境 |
| 变量合并 | 文档 ID、时间窗口和主数据单位是否匹配 |
| 论文解释 | 不夸大文本变量的测量有效性和因果含义 |

## 三、核心概念

### 1. 文本结果不等于研究变量

词频、主题、情感、embedding、LLM 标签只是中间结果。能否成为研究变量，取决于它是否对应清楚的理论构念，并且有可复核的测量逻辑。

### 2. LLM 标注不是免人工标注

LLM 可以提高标注效率，但必须有 codebook、样本抽查、一致性检验、错误类型分析和版本记录。不能让 LLM 自己发明标签或扩展标签定义。

### 3. 主题模型不能自动产生理论

LDA 或 BERTopic 生成的是文本共现或语义聚类。研究者需要用文献、理论和文本样例解释主题，不能直接把主题词命名为复杂理论构念。

### 4. 数据泄漏是文本建模高发问题

重复文本、同一作者、同一企业、同一事件、同一模板文本跨训练/测试，会让模型指标虚高。文本建模必须做泄漏审计。

### 5. 文本变量要能衔接实证模型

最终输出不是“模型准确率”，而是：

```text
doc_id / firm_id / user_id / date / text_variable_1 / text_variable_2 / ...
```

这些变量要能和第 08 讲的变量字典、假设映射和模型分析衔接。
