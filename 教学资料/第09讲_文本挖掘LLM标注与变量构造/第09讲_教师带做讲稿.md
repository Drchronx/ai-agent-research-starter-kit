# 第 09 讲教师带做讲稿

## 开场 0-8 分钟：纠正一个误区

今天这节课不是教大家做词云，也不是教大家让 LLM 批量打标签。词云、主题、情感、标签都只是中间产物。科研中真正需要的是一个能被审稿人接受的文本变量。

教师强调：

```text
文本变量 = 理论构念 + 文本证据 + 可复现规则 + 可靠性审计 + 可进入实证模型的数据表
```

## 8-18 分钟：展示最终工作区

打开第9讲模板文件夹，让学生看到最终交付物：

- `text_data_inventory.xlsx`
- `text_cleaning_plan.md`
- `text_variable_definition.md`
- `annotation_codebook.md`
- `annotation_sample.xlsx`
- `feature_dictionary.xlsx`
- `features.xlsx`
- `reliability_report.md`
- `variable_construction_report.md`
- `qc/text_variable_audit.md`

教师话术：

这些文件形成一条证据链。将来论文里写“我们用文本挖掘构造 AI 关注度变量”，必须能从变量一路追溯到文本来源、清洗规则、词典/模型、标注准则和人工核验。

## 18-30 分钟：创建工作区与复制 Skills

带学生执行工作区命令。

重点提醒：

- Skills 放工作区，不放 Codex 根目录。
- 原始文本放 `data/raw`。
- 清洗结果放 `data/clean`。
- 所有试错写 `research_log.md`。

教师现场检查：

```powershell
Get-ChildItem .\skills
Get-ChildItem .\data
```

## 30-42 分钟：文本数据盘点

让学生把一个样例数据放入 `data/raw`。如果没有真实数据，可以先用自己准备的 20 条 AI 工具评论作为样例。

教师带做提示词：

```text
请读取 data/raw/ 下的文本数据，生成 textmining/text_data_inventory.xlsx 的内容草稿。
重点检查 doc_id、text、source、date、重复文本、空文本、个人信息和版权风险。
```

教师纠错：

- 没有 ID 的文本不能直接进入变量构造。
- 只看文本列不够，要知道来源、时间和分析单位。
- 含个人信息的访谈或社媒文本必须先脱敏。

## 42-55 分钟：文本变量定义

教师讲清变量构造逻辑：

弱做法：

```text
我用情感分析算一个情绪变量。
```

强做法：

```text
我要测量用户对 AI Agent 的不确定性感知线索。文本证据包括“可能出错”“需要人工核验”“不确定来源”等表达。该变量不能代表真实风险，只代表文本中的不确定性表达强度。
```

让学生填写：

```text
text_variable_definition.md
```

教师现场问学生三个问题：

1. 你的变量代表什么构念？
2. 文本中什么证据算正例？
3. 什么文本看起来相关但不能算？

## 55-68 分钟：技术路线选择

教师展示路线表：

- 探索词汇：分词、词频、TF-IDF。
- 已有理论词典：词典法。
- 态度或情绪：情感分析。
- 发现主题：LDA/BERTopic。
- 已有标签样本：监督分类。
- 标签复杂且需要语义判断：LLM 标注。
- 比较政策、战略、论文文本相似度：embedding similarity。

教师强调：

不要为了看起来高级就用 BERT 或 LLM。简单词典能稳健回答问题时，复杂模型反而增加解释成本。

## 68-80 分钟：Codebook 与 LLM 标注

带学生写 `annotation_codebook.md`。

教师讲解：

- 标签定义必须让两个学生独立标注时尽量得到同一结果。
- 正例、反例、边界例缺一不可。
- LLM 不允许自行扩展标签。
- 不确定必须允许标为 `uncertain`，不能强行二分。

安全提醒：

```text
API key 只放环境变量，不写入 Markdown、Excel、脚本或聊天记录。
```

## 80-92 分钟：可靠性审计

教师解释一致性指标：

- 一致率：直观，但不控制随机一致。
- Cohen's Kappa：两个标注者常用。
- Krippendorff's Alpha：多标注者、多类型标签更通用。
- precision/recall/F1：有最终人工标签时可用。

教师强调：

LLM 标注准确率高不等于变量有效。还要看它错在哪里，是否系统性错标某类文本。

## 92-105 分钟：构造 features.xlsx

教师展示最终表：

```text
doc_id, source, date, uncertainty_label, sentiment_score, topic_ai_governance_prob, text_length
```

如果分析单位是企业-年：

```text
firm_id, year, ai_attention_score, risk_expression_ratio, topic_digital_strategy_prob
```

教师提醒：

变量聚合必须写规则。例如按企业-年聚合时，是取均值、总和、比例，还是最大值。

## 105-115 分钟：审计

让学生生成：

```text
qc/text_variable_audit.md
```

教师重点看：

- 变量和理论是否匹配。
- 是否有隐私/版权风险。
- 是否有数据泄漏。
- 是否过度解释 LLM 标签。
- 是否能和第8讲模型衔接。

## 115-120 分钟：收尾

教师总结：

今天真正完成的不是一个 NLP 分析，而是一个文本变量生产线。后续第8讲可以直接使用 `features.xlsx`，但只有通过 `text_variable_audit.md` 的变量才建议进入论文模型。
