# 第 05 讲零基础实操教程：文献综述、理论建构与研究问题生成

本讲目标不是让学生“听懂文献综述是什么”，而是让学生在电脑上完成一套可检查的科研产出：

```text
真实文献与论文卡片
→ 文献树
→ 研究流派与争议
→ 研究缺口候选池
→ 缺口审计
→ 理论机制链
→ 可检验假设组
→ 一页研究方案
→ 导师前审计报告
```

适用对象：完全没有 AI Agent 使用经验，但已经完成第 01-04 讲基础材料的学生。

建议课时：4 小时课堂实操 + 2 小时课后整理。

合格标准：

- 每个核心结论都能追溯到真实论文、论文卡片或手动核验记录。
- 文献综述不是逐篇摘要，而是围绕问题、理论、机制、变量、方法、证据强弱展开。
- 研究缺口不是“研究较少”，而是说明现有解释在哪个情境、机制、测量或方法上失效。
- 理论不是标签，必须解释变量之间为什么会发生关系。
- 假设能被具体数据、实验或模型检验。
- 一页研究方案能让导师在 3 分钟内判断是否值得继续做。

## 1. 课前材料检查

不要让 Agent 凭空补文献。按下面规则处理：

| 缺少材料 | 临时处理方式 | 质量限制 |

| 没有矩阵 | 先用本讲 `evidence_table.md` 替代 | 理论与变量分析会较粗 |
| 没有研究问题图谱 | 用研究日志中的个人方向替代 | 选题比较容易发散 |

你是科研选题、文献综述与理论建构助手。

## 研究场景
用户研究方向可能涉及管理学、心理学、神经科学、人机交互、神经营销、脑机接口、文本挖掘、机器学习和深度学习。

## 基本原则
- 只使用用户提供的真实文献、已核验 BibTeX、论文卡片和可核验检索结果。

- 假设必须可检验，并说明对应设计、测量和分析方法。

## 本讲输出
- review/evidence_table.md
- review/literature_tree.md
- review/research_streams_and_controversies.md
- review/research_gap_candidates.md
- review/research_gap_audit.md

- theory/theory_mechanism_chain.md
- hypotheses/hypothesis_set.md
- proposal/one_page_research_proposal.md
- qc/citation_reality_check.md
- qc/gap_and_theory_audit.md

## 回答风格
- 直接、准确、可执行。
- 每个判断说明证据来源。
- 对薄弱想法要指出问题并给出修改方案。

## 7. 第一次喂给 Agent：生成证据表

先不要让 Agent 直接写综述。第一步是把材料整理成证据表。

给 Agent 的提示词：

```text
请读取 input/paper_cards、input/candidate_papers.xlsx 和 input/matrices 中的材料，生成 review/evidence_table.md。

要求：
1. 不要写文献综述正文。
2. 只做结构化整理。
3. 每篇文献至少提取：
   - citation_key 或待核验标识
   - 研究问题
   - 理论或解释框架
   - 自变量/操纵变量
   - 中介机制
   - 调节变量/边界条件
   - 因变量
   - 数据来源或实验设计
   - 分析方法
   - 核心发现
   - 局限
   - 可复用启发
4. 如果某项没有依据，请写“未提供”，不要猜。
5. 如果引用真实性无法确认，请标注“待核验”。
```

`review/evidence_table.md` 应该像这样：

```markdown
| ID | 文献 | 问题 | 理论 | IV/操纵 | 机制 | DV | 方法 | 发现 | 局限 | 启发 |
|---|---|---|---|---|---|---|---|---|---|---|
| P01 | 已核验 citation_key |  |  |  |  |  |  |  |  |  |
```

人工核验：

- [ ] 不是让 Agent 自己补论文。
- [ ] “理论”列不是空泛名词。
- [ ] “方法”列能看出是实验、问卷、二手数据、文本挖掘、EEG/ERP 还是建模。
- [ ] “局限”列不能全是“样本有限”。

## 8. 第二次喂给 Agent：生成文献树

文献树不是文献列表，而是领域结构图。

给 Agent 的提示词：

```text
基于 review/evidence_table.md，生成 review/literature_tree.md。

请建立两棵树：

一、Novelty Tree
按贡献类型组织已有研究：
- 理论解释
- 新变量/新构念
- 新情境/新对象
- 新方法/新数据
- 新机制/边界条件

二、Challenge-Insight Tree
按“挑战-已有解决方式-未解决问题”组织：
- 这个领域面对什么核心挑战？
- 已有研究如何解释或解决？
- 哪些解释仍然不足？
- 哪些方法或数据还不能回答关键问题？

要求：
1. 不要按年份排列。
2. 不要逐篇摘要。
3. 每个分支至少列出代表文献或待核验文献。
4. 对每个分支说明它对我的研究方向有什么启发。
5. 不确定的地方标注“需要补充检索”。
```

合格的文献树应有这种结构：

```markdown
# Literature Tree

## 1. Novelty Tree

### 1.1 理论解释类
- 已有解释：
- 代表文献：
- 能解释什么：
- 不能解释什么：
- 对我的启发：

### 1.2 新机制/边界条件类
...

## 2. Challenge-Insight Tree

### 2.1 挑战一：
- 挑战定义：
- 已有解决方式：
- 未解决问题：
- 代表文献：
- 对我的启发：
```

人工核验：

- [ ] 文献树是否按“问题结构”组织，而不是按作者年份组织。
- [ ] 每个分支是否有代表文献。
- [ ] 是否能看出已有理论解释的边界。
- [ ] 是否有“需要补充检索”的空白点。

## 9. 第三次喂给 Agent：提取研究流派与争议

研究流派回答“领域内部有哪些解释路线”。争议回答“为什么已有研究结果或解释不一致”。

给 Agent 的提示词：

```text
基于 review/evidence_table.md 和 review/literature_tree.md，生成 review/research_streams_and_controversies.md。

请输出：
1. 3-5 个主要研究流派。
2. 每个流派的核心问题、常用理论、关键变量、常用方法、代表文献、局限。
3. 2-4 个主要争议。
4. 对每个争议判断来源：
   - 理论解释不同
   - 样本或情境不同
   - 测量方式不同
   - 实验/识别策略不同
   - 数据来源不同
5. 每个争议说明它是否可能形成我的研究缺口。

不要把所有差异都写成“研究视角不同”。必须说明具体差异。
```

输出结构：

```markdown
# Research Streams and Controversies

## 1. 研究流派

### Stream 1：
- 核心问题：
- 理论基础：
- 关键变量：
- 常用方法：
- 代表文献：
- 局限：
- 对我的启发：

## 2. 主要争议

### Controversy 1：
- 争议是什么：
- 冲突来自哪里：
- 证据：
- 是否能转化为研究缺口：
```

人工核验：

- [ ] 每个流派都能对应真实文献。
- [ ] 每个争议都有具体来源。
- [ ] 没有把“我不熟悉”写成“领域存在争议”。

## 10. 第四次喂给 Agent：生成研究缺口候选池

研究缺口至少有 6 种类型：

| 类型 | 说明 | 常见错误 |
|---|---|---|
| 理论缺口 | 现有理论不能解释新现象或关键关系 | 只贴一个新理论名 |
| 机制缺口 | 知道 X 影响 Y，但不知道为什么 | 把中介硬塞进去 |
| 边界缺口 | 关系在不同条件下强弱不同 | 为了复杂而加调节 |
| 测量缺口 | 现有测量不能捕捉关键构念 | 只是换一个量表 |
| 方法缺口 | 现有方法不能回答关键问题 | 只炫技，不服务问题 |
| 情境缺口 | 新场景改变了原有机制 | 只是换样本 |

给 Agent 的提示词：

```text
基于 review/literature_tree.md、review/research_streams_and_controversies.md 和 review/evidence_table.md，生成 5-8 个研究缺口候选，输出 review/research_gap_candidates.md。

每个缺口必须包含：
1. gap_id
2. 缺口类型：理论/机制/边界/测量/方法/情境
3. 已知内容：已有研究已经说明了什么
4. 未知内容：仍然不知道什么
5. 为什么重要：理论价值和实践价值
6. 支持证据：来自哪些真实文献或论文卡片
7. 可能研究问题
8. 可行方法：情景实验、问卷、EEG/ERP、文本挖掘、机器学习、因果推断等
9. 风险：可能被审稿人质疑什么
10. 需要补充检索什么

禁止使用空话：
- 已有研究较少
- 国内外研究不足
- 具有重要意义
- 填补空白
除非后面给出具体证据。
```

人工核验：

- [ ] 每个缺口有类型。
- [ ] 每个缺口说明“已知”和“未知”。
- [ ] 每个缺口有真实文献支撑。
- [ ] 每个缺口有可执行方法。
- [ ] 没有把“换样本、换平台、换情境”直接包装成贡献。

## 11. 第五次喂给 Agent：做缺口审计

缺口审计的目的：删掉不成立的选题。

给 Agent 的提示词：

```text
请基于 review/research_gap_candidates.md，使用严格审稿人标准生成 review/research_gap_audit.md。

对每个 gap 做以下审计：
1. 这个 gap 是否已经被已有研究解决？
2. 是否只是新样本、新平台或新情境？
3. 是否需要新理论、新机制、新测量或新方法？
4. 是否有真实文献证据支持“现有解释不足”？
5. 是否能在 3-6 个月内完成一个最小可行研究？
6. 是否适合管理学/心理学/神经科学/计算机科学交叉投稿？
7. 最大审稿风险是什么？
8. 最终判断：keep / revise / drop。

要求：
- 对每个 gap 都给出反证检索建议。
- 不要为了保留选题而降低标准。
- 对 drop 的 gap 给出删除理由。
- 对 revise 的 gap 给出具体修改方向。
```

审计表格式：

```markdown
| gap_id | 是否已被解决 | 是否只是换情境 | 需要的新贡献 | 可行性 | 审稿风险 | 决策 |
|---|---|---|---|---|---|---|
```

人工核验：

- [ ] 是否至少删除或修改 1 个弱缺口。
- [ ] 是否对每个保留缺口写出反证检索词。
- [ ] 是否避免“所有想法都很好”的迎合式结果。

## 12. 第六次喂给 Agent：选择最强研究问题

用评分表筛选。

```markdown
| gap_id | importance | novelty | feasibility | theory_value | method_fit | evidence_support | total | decision |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| G1 |  |  |  |  |  |  |  | keep/revise/drop |
```

评分说明：

- `importance`：问题是否重要。
- `novelty`：是否真有新意。
- `feasibility`：数据、实验、时间、能力是否可行。
- `theory_value`：是否能推进理论解释。
- `method_fit`：是否适合你的方法能力。
- `evidence_support`：是否有足够真实文献支持。

给 Agent 的提示词：

```text
请基于 review/research_gap_audit.md，对所有 keep/revise 的 gap 打分。

评分维度：
- importance 1-5
- novelty 1-5
- feasibility 1-5
- theory_value 1-5
- method_fit 1-5
- evidence_support 1-5

请输出：
1. gap_score_table
2. 排名前 2 的 gap
3. 推荐主选题
4. 备选选题
5. 为什么其他 gap 暂时不做
6. 主选题的一句话研究问题
```

研究问题公式：

```text
在 [具体情境] 中，[核心自变量/刺激/技术特征] 如何通过 [心理/认知/神经/组织机制] 影响 [结果变量]，并受到 [边界条件] 的影响？
```

例子：

```text
在科研任务场景中，AI Agent 的解释透明度如何通过降低不确定性感知并提升信任，影响博士生对 Agent 建议的采纳意愿？
```

这只是示范句，不是直接可投稿题目。真实研究必须回到你的文献和数据。

## 13. 第七次喂给 Agent：建立理论机制链

理论机制链必须区分 5 件事：

| 层次 | 含义 | 例子 |
|---|---|---|
| 情境/刺激 | 研究中发生变化的场景或操纵 | AI 解释透明度高/低 |
| 构念 | 理论层面的抽象概念 | 不确定性感知、信任 |
| 变量 | 可测量或可操纵的指标 | 量表得分、行为选择 |
| 机制 | 为什么 X 会影响 Y | 信息可解释性降低不确定性 |
| 结果 | 最终被解释的行为或绩效 | 采纳意愿、任务表现 |

给 Agent 的提示词：

```text
请基于我选择的最强研究问题，使用 theory_mechanism_chain_template.md，生成 theory/theory_mechanism_chain.md。

要求：
1. 明确情境/刺激/技术变化。
2. 明确心理、认知、神经或组织机制。
3. 区分构念、变量、测量和操纵。
4. 说明理论为什么能解释这个机制。
5. 指出理论不能解释或需要谨慎的地方。
6. 给出适合的研究设计：
   - 情景实验
   - 问卷/量表
   - EEG/ERP
   - 文本挖掘
   - 机器学习/深度学习
   - 因果推断
7. 禁止只写理论名称。
```

输出结构：

```markdown
# Theory Mechanism Chain

## 1. 核心研究问题

## 2. 理论解释
- 使用理论：
- 理论核心命题：
- 为什么适配本问题：
- 不适配或需要限制的地方：

## 3. 机制链
情境/刺激 → 心理/认知机制 → 行为/态度/绩效结果

## 4. 构念-变量-测量映射
| 构念 | 变量角色 | 操纵/测量 | 数据来源 | 风险 |
|---|---|---|---|---|

## 5. 可选研究设计
```

人工核验：

- [ ] 理论真的解释机制，而不是只提供名词。
- [ ] 构念和测量没有混为一谈。
- [ ] 每个变量都有可测量或可操纵方案。
- [ ] 理论边界被写出来。

## 14. 第八次喂给 Agent：生成假设组

假设不是变量关系口号。每个假设都应包含机制、证据、设计和分析。

给 Agent 的提示词：

```text
请基于 theory/theory_mechanism_chain.md，使用 hypothesis_set_template.md，生成 hypotheses/hypothesis_set.md。

要求：
1. 只生成理论上必要的假设，不要为了复杂而添加中介和调节。
2. 每个假设包括：
   - 假设编号
   - 假设文本
   - 机制解释
   - 文献支持或待核验文献
   - 操纵或测量方式
   - 数据分析方法
   - 因果语言风险
3. 至少包含一个主效应或核心关系假设。
4. 只有当理论机制充分时，才写中介假设。
5. 只有当边界条件有理论依据时，才写调节假设。
6. 如果没有实验或识别策略，不要写“导致”“因果影响”。
```

假设质量检查：

| 问题 | 不合格写法 | 修改方向 |
|---|---|---|
| 只有关系 | X 正向影响 Y | 写清楚为什么影响 |
| 中介硬塞 | X 通过 M 影响 Y | 说明 M 为什么是过程机制 |
| 调节硬塞 | W 调节 X 与 Y | 说明 W 为什么改变关系强度 |
| 因果过度 | 问卷证明 X 导致 Y | 改成“相关”“关联”，或补实验设计 |

人工核验：

- [ ] 提纲有问题推进。
- [ ] 每一节都服务于研究问题。
- [ ] 文献不是简单堆砌。

## 18. 课堂示范案例

示范方向：

```text
AI Agent 在科研任务中的解释透明度如何影响博士生对其建议的采纳？
```

注意：这个案例只用于演示结构。真实课程中不能直接复制作为论文题目。

### 18.1 示例研究问题压缩

模糊想法：

```text
我想研究 AI Agent 对科研效率的影响。
```

问题：

- “AI Agent”太泛。
- “科研效率”太泛。
- 没有机制。
- 没有任务场景。
- 没有可检验设计。

压缩后：

```text
在文献筛选任务中，AI Agent 的解释透明度是否通过降低不确定性感知并提升信任，增加博士生采纳 AI 推荐文献的意愿？
```

进一步方法化：

```text
设计 2 组情景实验：
高解释透明度 vs. 低解释透明度；
测量不确定性感知、信任、采纳意愿与实际采纳行为；
使用中介模型检验机制。
```

如果加入 EEG/ERP：

```text
把“解释透明度”作为刺激材料特征，记录文献推荐判断过程中的认知负荷或冲突加工相关指标；
但必须先确认 EEG 指标与心理机制之间的理论对应，不能把脑电指标当作装饰。
```

### 18.2 示例缺口写法

弱缺口：

```text
已有研究很少关注 AI Agent 在科研中的应用。
```

强一些的缺口：

```text
已有研究多讨论 AI 建议采纳或自动化信任，但在科研文献筛选这类高不确定、高专业判断任务中，解释透明度是否通过降低不确定性感知影响采纳，仍需要结合任务情境和行为数据进行检验。
```

还需要核验：

- 已有研究是否已经讨论“解释透明度—信任—采纳”。
- 科研任务场景是否真的改变机制。
- 不确定性感知是否比信任更接近过程机制。
- 采纳意愿和实际采纳行为是否一致。

## 19. 常见错误与修正

### 错误 1：让 Agent 直接写综述正文

问题：模型会把不完整材料包装成流畅文字，容易掩盖证据不足。

修正：先生成 `evidence_table.md`、`literature_tree.md` 和 `research_gap_audit.md`，再写综述提纲。

### 错误 2：把研究缺口写成“研究较少”

问题：审稿人会问“你怎么知道少？少为什么重要？”

修正：写成“现有解释在哪个机制、情境、方法或测量上不足”。

### 错误 3：理论只写名称

问题：理论没有解释变量关系。

修正：写清楚理论命题、心理或认知机制、变量角色和边界条件。

### 错误 4：假设过度复杂

问题：为了看起来高级，硬加中介、调节、调节中介。

修正：只有机制有理论依据才写中介，只有边界条件能改变关系强度才写调节。

### 错误 5：AI 编造文献

问题：文献看起来像真的，但 DOI、题名或作者不存在。

修正：所有引用进入正文前必须经过 Ai4Scholar、AMiner、OpenAlex、Zotero 或 DOI 页面核验。

### 错误 6：方法和问题不匹配

问题：想回答因果问题，但只有横截面问卷。

修正：要么改成关联性语言，要么增加实验、纵向、准实验或识别策略。
